# CreditShield v0.1.0

**Release Date:** November 2026

Initial release of CreditShield loan origination platform with AI-powered risk assessment.

## Overview

CreditShield v0.1.0 delivers a complete digital lending platform for managing loan applications from borrower onboarding through final underwriting decision. The platform combines automated policy enforcement, explainable AI analysis, and human oversight to accelerate loan origination while maintaining credit quality.

## Key Features

### 7-Stage Loan Origination Workflow

Complete workflow implementation covering:

1. Lead and Application Intake
2. KYC and Document Collection
3. Eligibility and Rule Screening
4. Credit Analysis
5. Underwriting Decision
6. Offer and Acceptance
7. Post-Decision Handover

Each stage includes role-specific workflows, automated transitions, and complete audit trail.

### AI-Powered Risk Assessment

- **LLM Integration:** AWS Bedrock with Meta Llama 3 70B Instruct for explainable credit decisions
- **RAG Document Retrieval:** FAISS-based semantic search over RBI circulars and lending policies
- **4-Page Appraisal Reports:** Bank-grade professional reports for loan officers
- **Dual Validation:** AI outputs undergo validation and auto-correction
- **Mock Mode:** Full functionality available without AWS credentials for development

### 50+ Underwriting Rules

Automated policy enforcement across 5 risk categories:

- Income Stability
- Credit Behaviour
- Financial Discipline
- Loan Burden
- Lifestyle Risk

Hard rules auto-reject. Soft rules trigger manual review. All violations include regulatory citations retrieved via RAG.

### Multi-Role Access Control

Distinct workflows for:

- Borrowers (mobile and web)
- Loan Officers
- Credit Analysts
- Field Officers
- Underwriters (Branch Managers)
- System Administrators

JWT-based authentication with role-based permissions.

### RESTful API

FastAPI-based backend with:

- 30+ API endpoints
- OpenAPI/Swagger documentation
- JWT authentication
- Borrower journey APIs
- Risk analysis endpoints

### Technology Stack

- **Backend:** FastAPI + PostgreSQL
- **AI:** AWS Bedrock (Llama 3 70B, Titan Embeddings) + FAISS
- **Frontend:** React + Vite web dashboard, Flutter mobile app
- **Deployment:** Docker + Kubernetes support

## Supported Loan Products

- Personal loans
- Education loans
- Business loans
- Micro loans
- Buy Now Pay Later (BNPL)

## Known Limitations

### P0 Release Constraints

- Database tables not auto-created at startup (manual setup required)
- Limited bureau integration (CIBIL scores must be provided externally)
- No post-disbursal loan servicing
- RAG vector store in-memory only (pgvector backend planned for future release)

### AI Features

- Mock mode uses canned responses (AWS Bedrock required for production)
- Prompt format optimized for Llama 3 (alternative models may require code changes)
- RAG chunking uses simple heading-based splitting (semantic chunking planned)

## API Endpoints Added

### Authentication
- `POST /api/v1/auth/login` — Internal user login
- `POST /api/v1/borrower/auth/signup` — Borrower registration
- `POST /api/v1/borrower/auth/login` — Borrower login
- `GET /api/v1/borrower/auth/me` — Get borrower profile

### Borrower Journey
- `GET /api/v1/borrower/kyc/status` — KYC status
- `POST /api/v1/borrower/kyc/complete` — Complete KYC
- `POST /api/v1/borrower/eligibility/check` — Check eligibility
- `GET /api/v1/borrower/loan-types` — List loan products
- `POST /api/v1/borrower/applications` — Create application
- `GET /api/v1/borrower/applications/current` — Get current application
- `GET /api/v1/borrower/documents/required` — List required documents
- `POST /api/v1/borrower/consent/submit` — Submit consent
- `GET /api/v1/borrower/rbi/checkpoint` — RBI compliance check
- `GET /api/v1/borrower/risk-score` — Get risk score
- `GET /api/v1/borrower/offers` — List offers
- `POST /api/v1/borrower/offers/{offer_id}/select` — Select offer
- `GET /api/v1/borrower/agreement` — Get agreement
- `GET /api/v1/borrower/dashboard` — Dashboard data
- `GET /api/v1/borrower/tracker` — Application tracker
- `GET /api/v1/borrower/notifications` — Notifications

### Risk Analysis
- `POST /api/v1/risk/professional-report` — Generate appraisal report

### System Health
- `GET /health/db` — Database connectivity check

## Environment Variables Added

### Backend
- `DATABASE_URL` — PostgreSQL connection
- `JWT_SECRET_KEY` — JWT signing key
- `JWT_ALGORITHM` — JWT algorithm
- `SYSTEM_ADMIN_USERNAME` — Admin username
- `SYSTEM_ADMIN_PASSWORD` — Admin password

### AI Agent
- `AWS_REGION` — Bedrock region
- `AWS_ACCESS_KEY_ID` — AWS credentials
- `AWS_SECRET_ACCESS_KEY` — AWS credentials
- `MOCK_MODE` — Enable mock mode
- `BEDROCK_MODEL_ID` — LLM model
- `BEDROCK_EMBEDDING_MODEL` — Embedding model
- `MAX_TOKENS` — LLM generation limit
- `TEMPERATURE` — LLM temperature
- `RAG_TOP_K` — RAG retrieval count
- `RAG_CHUNK_SIZE` — Document chunk size
- `RAG_CHUNK_OVERLAP` — Chunk overlap
- `VECTOR_STORE` — Vector DB backend
